# 英法选词与法语响应回归测试

本组验证 `Option + 当前页编号` 选择英文、`Ctrl + 当前页编号` 选择法语，同时保留 Lua 词汇的第一／第二义项快捷键。

在仓库根目录运行，并显式指定测试配置与匹配运行库：

```sh
python3 tests/native/sentence-selection/run.py \
  --frontend frontend/source \
  --work-root work \
  --source-user "/path/to/test/Rime" \
  --bundle "/path/to/matching/Squirrel.app"
```

可以用 `--frontend` 指定含源码、librime 头文件的鼠须管前端目录，用 `--bundle` 指定现有鼠须管程序。测试配置需要已部署的雾凇搜狗双拼、九候选与双 Shift 默认设置，详见同级上层的原生引擎测试说明。需要 Xcode 命令行工具。未显式指定时默认从 `~/Library/Rime` 复制编译词典、配置和依赖 Lua 到独立 `work/` 临时目录，使用交付目录的最新 `en_gloss.lua`；不复制或并发打开中文用户词频库，不安装、不注册、不切换系统输入源。

## 覆盖

- `SelectionTests.swift`：83 条状态及路由断言。使用真实 Rime 生成的 `今天下午我們一起去圖書館` 快照以及 Apple 实际译文；检查待译、过期、输入恢复成同一句后的旧请求、页面／候选／光标／客户端变化、完整 composition 范围、英法物理数字键以及修饰键回退。
- `ControllerTests.swift`：85 条控制器断言。编译交付版本的实际 Controller、按键映射和状态辅助代码，连接真实 librime/librime-lua，并用真实 `NSEvent` 依次发送 Option／Ctrl 按下、数字按下。
- 验证英文完成后按 Option 不会取消结果；即使按键字符是 `¡`，物理数字 1 仍选择第一候选译文。
- 验证清除 marked text 后才插入完整英文，两个动作均使用当前标记／插入范围，测试客户端中的已有聊天正文保持不变。
- 验证没有译文、未完成或过期结果不会错误提交；有已选前缀或未转换后缀时不发起不能完整提交的整句翻译。
- 验证原 Lua `Option + 1` 的 `hello` 和 `Shift + Option + 1` 的 `hi` 仍正常。

`fixtures/example-context.json` 来自实际 Rime 引擎；`fixtures/example-translation.json` 来自实际 Apple 本机翻译及前端绘制联调。结果及被测产品源码 SHA-256 保存在 `results.json`。

新增法语检查：词语与整句批量请求、当前页去重上限、修饰键刷新保留译文、英法先后到达互不覆盖、旧回调与隐藏窗口保护、开关同时停用，以及有法语时英文快捷键保持原义。

法语响应与选取检查：缓存译文在首次绘制同步出现；未命中项在 140 毫秒测试窗口内开始请求（产品防抖为 80 毫秒）；批次未结束即可显示已返回条目；移动高亮不取消同页任务。Ctrl 的 1–9 物理键均选中对应译文，支持完整句子、非首位词语、第二页、已确认中文前缀、未转换后缀及位于中间的光标。等待中或过期的法语不会提交中文，也不会丢失输入；没有候选菜单时 Ctrl 数字交给应用。Lua 另外有 72 条单元断言，其中验证一次性请求在输入、光标、页码、编号、词条或译文不匹配时被拒绝并清理。

## 验证边界

控制器测试仅把 InputMethodKit 宿主、文本客户端、候选面板和异步翻译完成回调换成小型测试替身；Controller 的方法体、原生按键事件和 Rime 引擎均为真实实现。它不创建系统 IMK 服务，也不自动操作任何聊天应用。真实聊天框能否正确接收输入以及视觉交互仍需应用内验收。
